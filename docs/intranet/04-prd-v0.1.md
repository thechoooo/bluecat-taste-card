# 블루캣 인트라넷 PRD v0.1

- 작성일: 2026-10-29
- 상태: 초안. 영상(CVmbidt-3ro) 본문 반영 전. `[영상 보강]` 표시는 자막 확보 후 채운다.
- 공개 저장소 원칙: 내부 수치(단가, 인건비, 매출, 계정 ID)는 적지 않는다. 필요한 수치는 `[별도 보관]`으로 표시한다.

## 1. 배경과 문제 정의

블루캣(주식회사 페즈)은 칵테일 바 매장이다. 운영에 필요한 반복 업무가 여러 도구에 흩어져 있다.

| 업무 | 지금 방식 | 문제 |
|---|---|---|
| 월 반복 지출 품의 | 거래처별 품의서 양식을 재사용해 PDF를 만들고 지메일 초안을 작성하는 스킬이 있다 | 결과물이 메일과 드라이브에 흩어져 집계가 안 된다 |
| 법인카드 승인내역 정리 | 엑셀과 영수증 사진을 대조해 사용내역·비고를 채우는 스킬이 있다 | 월 마감 때 한 번에 처리해 오류를 늦게 발견한다 |
| 메타 광고 성과 | Graph API 조회 스크립트가 있다(토큰 미발급) | 리포트가 자동 생성되지 않는다 |
| 인스타그램 게시 | 수작업 | 문구·이미지 제작과 게시가 사람 손에 묶여 주기가 불규칙하다 |
| 거래처·발주, 재고, 인력·근무, 매출·정산, 고객 | 현황 미조사 | 기록 위치와 방식을 모른다 |

핵심 문제는 "자동화 조각은 있는데 한곳에 모이지 않는다"는 것이다. 인트라넷은 새 기능을 만드는 것보다 **기록이 모이는 자리**를 먼저 만든다.

## 2. 목표와 성공 지표

### 목표
1. 모든 운영 기록이 한 체계 안에 쌓인다.
2. 반복 업무는 에이전트가 초안을 만들고, 대표이사가 승인한다.
3. 매장 규모에 맞게 무료·저비용 도구로 조립한다.

### 성공 지표 (1차 출시 기준)
| 지표 | 현재 | 목표 |
|---|---|---|
| 품의서 1건 작성 소요 시간 | `[별도 보관]` | 초안 자동, 승인 1회 클릭 |
| 카드내역 월 마감 소요 시간 | `[별도 보관]` | 주 단위 자동 대조로 월 마감 시 확인만 |
| 광고 성과 리포트 | 수동 | 매일 자동 생성, 수동 0회 |
| 인스타 게시 1건 제작 시간 | `[별도 보관]` | 초안 자동, 승인 후 게시 |
| 주간 인스타 게시 수 | `[별도 보관]` | 목표치는 2차에 정한다 |

## 3. 사용자와 역할

| 역할 | 하는 일 | 권한 |
|---|---|---|
| 대표이사 | 모든 승인, 예산 결정, 도구 구독 결정 | 읽기·쓰기·승인 전부 |
| 운영 담당(두나·헨리·재키 등) | 품의 요청, 카드 영수증 등록, 재고·근무 기록 | 자기 업무 영역 읽기·쓰기 |
| 에이전트(Claude) | 초안 생성, 대조, 리포트, 게시 실행 | 쓰기는 초안까지. 승인 없이는 돈·외부 게시 실행 불가 |
| 손님 | 취향 카드, QR | 공개 페이지만 |

역할별 세부 담당은 `[사용자 확인 필요]`.

## 4. 범위와 단계

1차 범위는 전부다. 다만 출시는 단계로 나눈다. 각 단계는 단독으로 쓸 수 있어야 한다.

| 단계 | 모듈 | 선정 이유 |
|---|---|---|
| 1단계 | 지출·품의, 법인카드, 거래처 마스터 | 자동화 스킬이 이미 있고 월 반복이 확실하다 |
| 1단계 | 마케팅 성과(메타 광고, 인스타 게시 기록) | API 스크립트가 있다 |
| 2단계 | 인스타 콘텐츠 파이프라인(문구→이미지→승인→게시) | 사용자 최종 목표. 이미지 제작·호스팅 방식 결정이 선행된다 |
| 2단계 | 매출·정산, 거래처·발주 | 지출과 매출이 모여야 정산이 된다 |
| 3단계 | 재고, 인력·근무, 고객 | 현황 조사 후 설계한다 |

## 5. 핵심 업무 흐름

### 5.1 월 반복 지출 품의
1. 거래처 증빙(거래명세표·계산서)이 도착한다.
2. 에이전트가 거래처 양식으로 품의서 초안(PDF)과 메일 초안을 만든다.
3. 대표이사가 승인한다.
4. 승인 시 품의 기록이 저장되고 메일이 발송된다.

### 5.2 법인카드 정리
1. 영수증 사진과 승인내역이 등록된다.
2. 에이전트가 거래를 대조해 사용내역·비고를 채우고 미대조 건을 표시한다.
3. 담당자가 미대조 건을 보완한다.
4. 월 마감 시 카테고리 소계가 자동 집계된다.

### 5.3 광고 성과 리포트
1. 매일 정해진 시각에 Graph API로 캠페인별 지표를 가져온다.
2. 시트에 적재하고 전일·전주 대비를 계산한다.
3. 이상(지출 급증, 성과 급락)이 있으면 대표이사에게 알린다. 캠페인 변경은 제안만 한다.

### 5.4 인스타 게시 (2단계)
1. 에이전트가 메뉴·시즌·성과 데이터로 주제를 고르고 문구를 쓴다.
2. 이미지를 만든다(방식 미결정).
3. 공개 URL에 이미지를 올린다(방식 미결정).
4. 대표이사가 초안을 승인한다.
5. 승인 시 `ig-publish.js --publish`가 실행되고 게시 기록이 저장된다.

`[영상 보강]` 윤자동 사례의 흐름과 비교해 빠진 단계를 보완한다.

## 6. 데이터 모델

| 엔터티 | 주요 필드 | 1차 저장 위치(안) |
|---|---|---|
| 거래처 | 이름, 유형(주류·유통·음악·인력·카드), 양식 ID, 결제 조건 | 시트 |
| 품의 | 거래처, 기간, 금액, 상태(초안·승인·발송), PDF 링크, 승인일 | 시트 + 드라이브 |
| 카드거래 | 승인일, 가맹점, 금액, 사용내역, 비고, 영수증 링크, 대조 상태 | 시트 |
| 캠페인 성과 | 날짜, 캠페인, 지출, 노출, 도달, 클릭 | 시트 (automation 출력) |
| 게시물 | 날짜, 주제, 문구, 이미지 URL, 상태, media ID, 성과 | 시트 |
| 재고·근무·고객 | 3단계에서 정의 | 미정 |

저장소 선택은 구글 시트를 1차 기본으로 둔다. 근거: 이미 Google Sheets·Drive가 연결되어 있고 무료이며, 기존 스킬이 엑셀 기반이다. 노션은 `[영상 보강]` 후 비교해 결정한다.

## 7. 통합

| 외부 시스템 | 용도 | 상태 |
|---|---|---|
| Meta Graph API | 광고 성과 조회, 인스타 게시 | 스크립트 있음, 토큰 미발급 |
| Google Sheets / Drive | 기록 저장, 품의서 PDF 보관 | 연결됨 |
| Gmail | 품의 메일 발송, 승인 알림 | 재연결 필요 |
| Canva | 이미지 제작 후보 | 연결 상태 미확인 |
| Metricool(무료) | 인스타 예약·분석 보조 | 유료 기능 사용 안 함 |

## 8. 권한과 승인 규칙

- 승인자는 대표이사 한 사람이다. 금액 기준은 없다.
- 에이전트는 돈이 나가는 일(품의 발송, 광고 예산 변경)과 외부 게시를 승인 없이 실행하지 않는다.
- 승인은 기록에 남긴다(누가·언제·무엇을).
- **미결 질문**: 모든 건을 한 사람이 승인하면 병목이 된다. "정기 반복 지출은 사후 보고"처럼 예외를 둘지 결정이 필요하다.

## 9. 비기능 요구

| 항목 | 요구 |
|---|---|
| 보안 | 토큰·계정 ID는 환경 시크릿에만 둔다. 공개 저장소에 내부 수치를 적지 않는다. 카드번호·개인정보는 마스킹한다 |
| 비용 | 월 예산 상한은 없으나 무료 우선. 유료 도구는 제안 후 대표이사가 결정한다. 도구마다 월 비용을 기록한다 |
| 신뢰성 | 외부 게시(POST)는 자동 재시도하지 않는다(중복 방지). 조회는 재시도한다 |
| 유지보수 | 빌드 없는 스크립트와 시트 중심으로 두어 개발자 없이 고칠 수 있게 한다 |
| 감사 | 에이전트의 모든 실행은 로그를 남긴다 |

## 11. 리스크와 미결 질문

### 리스크
| 리스크 | 영향 | 대응 |
|---|---|---|
| 범위 전부 + 예산 상한 없음 → 범위 팽창 | 1차 출시 지연 | 단계별 출시, 단계마다 완료 조건 고정 |
| 대표이사 단일 승인 병목 | 승인 대기 누적 | 예외 규칙 검토(8절) |
| 공개 저장소에 내부 정보 유입 | 정보 노출 | 수치 금지 원칙, 커밋 전 검사 |
| Meta 앱 심사·권한 지연 | 광고·게시 모듈 지연 | 자사 계정만 다루는 범위로 시작 |
| 이미지 품질(생성형) | 브랜드 손상 | 템플릿 방식 우선, 승인 게이트 유지 |

### 미결 질문
1. 승인 예외(정기 지출 사후 보고)를 둘 것인가
2. 이미지 제작 방식: Canva 템플릿 / 생성형 / 촬영 사진
3. 이미지 호스팅 방식(무료 범위)
4. 노션 vs 시트 — `[영상 보강]` 후 결정
5. 운영 담당자별 역할
6. 재고·근무·고객의 현재 기록 방식
7. `[영상 보강]` 윤자동 사례의 ERP 모듈 구성, 에이전트 경계, 실패 사례
